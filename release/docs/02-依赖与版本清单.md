## 4. MinIO 为什么锁定 2025-04-22

MinIO 官方在后续版本里移除了 Web 管理控制台（约 11 万行代码），新版本控制台连 Access Key
都无法配置，只剩一个对象浏览器。`RELEASE.2025-04-22T22-12-26Z` 是**最后一个带完整管理控制台**
的版本，因此刻意锁定，不跟随上游升级。

运维含义：

* 升级 MinIO 会丢掉控制台能力 → 不要随手升级；
* 应用只用最小权限账号（`dms-app` + 策略 `dms-files-rw`，只允许读写 `dms-files` 一个桶），
  root 账号仅用于控制台管理；
* 控制台只监听 `127.0.0.1:9001`，需走 SSH 隧道：
  `ssh -L 9001:127.0.0.1:9001 root@<服务器>` 后浏览 `http://localhost:9001`。

## 5. 可选组件：OnlyOffice

| 组件 | 版本 | 来源 | 体积 |
| --- | --- | --- | --- |
| Docker | 26.1.5 (`docker.io` 26.1.5+dfsg1-9+deb13u1) | Debian 13 源 | 约 100MB（含 containerd） |
| OnlyOffice Document Server | `onlyoffice/documentserver:latest`（23.7 系列） | docker.io 官方镜像 | 3.32GB |

* **不装也能用**：PDF/Office 预览回落为「服务端 LibreOffice 转 PDF + pdf.js」，
  图片/视频/音频/文本/CAD 等不受影响。装了才有无损观感的在线预览与在线编辑。
* 镜像体积占了发布包的大头，所以单独打包（`dms-release-1.0.0-onlyoffice.tar`），
  核心包不含它。
* JWT 默认关闭：文档服务只监听回环，对外只有 nginx 上那几个固定路径能进来。
  若要开启，需同时改两处（文档服务 `local.json` 的 secret 与应用的
  `dms.onlyoffice.secret` 系统参数），否则会报"下载失败/令牌校验不通过"。
* **缓存链接签名密钥必须三处一致**（容器环境变量 `SECURE_LINK_SECRET`、`local.json` 的
  `storage.fs.secretString`、nginx 的 `$secure_link_secret`）。不一致时**所有经 OnlyOffice
  渲染的格式都会「下载失败」，而图片/视频正常**——这是最容易误判成"对象存储坏了"的故障，
  实际与 MinIO 无关。`install-onlyoffice.sh` 会把密钥固定在
  `/opt/onlyoffice/.secure_link_secret` 并自动对齐三处。

## 7. 版本核对方法

部署后可在服务器上执行：

```bash
# 组件版本
java -version; psql --version; redis-server --version; nginx -v
/usr/local/bin/minio --version; /usr/local/bin/mc --version
soffice --version; ffmpeg -version | head -1

# 离线包清单（构建时生成，记录了每个 .deb 的包名与版本）
cat /path/to/release/offline/packages.list

# 应用侧依赖（jar 内）
unzip -l /opt/dms/dms-app.jar | grep -E "BOOT-INF/lib/(minio|tika|poi|jodconverter)" | head
```

页面侧：「系统信息」页会直接显示数据库版本、JVM 版本与启动参数、MinIO 配置与对象统计、
Redis 版本等——那是最快的"这套系统到底跑在什么版本上"的答案。
