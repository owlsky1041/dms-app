# DMS 文档管理系统 —— 部署手册

> 版本：1.0.0　　目标系统：**Debian 13 (trixie) / amd64**（本文所有命令都在该版本上验证过）
> 部署方式：**离线优先**——发布包自带全部系统依赖，目标服务器不需要外网。
> 预计耗时：20~40 分钟（其中解压与安装系统包约 10 分钟）。

---

## 0. 一分钟版

```bash
# 1) 把发布包传到服务器（任选一种：U 盘 / scp / 内网共享）
scp dms-release-1.0.0-core.tar.gz root@<服务器>:/root/

# 2) 校验 + 解压
cd /root && sha256sum -c dms-release-1.0.0-SHA256SUMS        # 应与文件名一致
tar xzf dms-release-1.0.0-core.tar.gz && cd dms-release-1.0.0

# 3) 一键安装（离线依赖就在包里）
./deploy/install.sh

# 4) 装完自检
./deploy/verify-deploy.sh

# 5)（可选）Office 在线预览
./deploy/install-onlyoffice.sh
```

装完浏览器打开 `http://<服务器IP>/`，账号 `admin`，口令在 `/root/.dms-credentials` 里
（`ADMIN_PASSWORD=`）。**第一次登录后请立刻改口令。**

## 1. 部署前检查

| 项目 | 要求 | 检查命令 |
| --- | --- | --- |
| 操作系统 | Debian 13 (trixie)，amd64 | `cat /etc/os-release; dpkg --print-architecture` |
| 内存 | ≥ 4GB（推荐 8GB） | `free -h` |
| 磁盘 | 系统盘 ≥ 20GB 可用（应用+依赖约 3GB） | `df -h /` |
| 权限 | root | `id -u` |
| 端口 | 22、80 可用（8080/8081/5432/6379/9000/9001 只在本机监听） | `ss -ltnp` |
| 网络 | 离线部署无需外网；在线部署需能访问 `deb.debian.org` | `getent hosts deb.debian.org` |

注意事项：

* **不要**在已经装了别家 nginx 默认站点的机器上直接装：安装脚本会移除
  `/etc/nginx/sites-enabled/default`（否则默认站点会抢 80 端口）。若这台机器上还跑着别的站点，
  请先与现有站点协调端口或 server_name。
* 若服务器**已经装了 PostgreSQL/Redis**，安装脚本会复用它们（只创建 `dms` 库与角色、
  给 Redis 设置 `requirepass`），不会覆盖已有数据库。
* 安装脚本可重复执行：口令不会重置，已有数据不会被动。

## 3. 安装

### 3.1 标准安装（离线）

```bash
cd /root/dms-release-1.0.0
./deploy/install.sh
```

脚本按 9 步执行，每步都有明确输出：

| 步骤 | 做什么 | 关键点 |
| --- | --- | --- |
| 1 环境预检 | 检查系统版本/架构/内存/磁盘/端口，确认发布包完整 | 缺文件**在动手前**就报错退出 |
| 2 安装系统依赖 | `offline/debs` 建临时本地 apt 源 → 安装 499 个包 | 用本地源而不是 `dpkg -i`，apt 才能处理依赖顺序 |
| 3 账号与目录 | 建 `dms`、`minio-user` 用户与全部目录 | 目录属主/权限按最小可用设置，配置目录 750 root:dms |
| 4 凭据 | 生成 DB/Redis/JWT/MinIO/管理员口令，写 `/root/.dms-credentials` | 随机强口令，**只生成一次**，重复安装不重置 |
| 5 数据库 | 建角色与库 → 灌基础结构 → 按 `dms_schema_migrations` 增量应用迁移 | 老库升级时按"对象是否已存在"补记录，不会重复执行 |
| 6 种子数据修整 | 停用演示账号 `test`/`test1`，对齐 `sys_oss_config` 到本机 MinIO | 框架默认数据不适合生产，必须当场处理 |
| 7 Redis | 设 `requirepass`、只监听回环、重启 | |
| 8 MinIO | 装二进制、写 `/etc/default/minio`、建桶与最小权限账号 | 应用只用 `dms-app` 账号，root 仅用于控制台 |
| 9 应用与 nginx | 落 jar/前端、生成配置、装 systemd 单元与 logrotate、配 nginx | JVM 堆按物理内存自适应（上限 4G） |
| 10 启动与设口令 | 启动服务、等待就绪、把管理员口令改成随机强口令并**当场验证** | 用初始口令登录成功后立即重置 |

常用参数：

```bash
./deploy/install.sh --dry-run                  # 只打印将执行的操作，不改系统
./deploy/install.sh --offline /root/offline    # 指定离线依赖目录（默认用包内 offline/）
./deploy/install.sh --online                   # 从网络 apt 安装（服务器能上外网时）
./deploy/install.sh --skip-packages            # 依赖自己已装好，跳过系统包安装
./deploy/install.sh --server-host 10.0.0.5     # 指定对外 IP/域名（OnlyOffice 回源地址用）
./deploy/install.sh --admin-password 'Xxx@2026'  # 指定初始管理员口令
./deploy/install.sh --with-onlyoffice          # 装完继续装 OnlyOffice
```

### 3.2 安装后自检

```bash
./deploy/verify-deploy.sh
```

自检跑 6 组、约 40 项：服务与端口、数据库表与数据、对象存储真实读写探测、
应用接口（登录/取权限/列目录/权限位/系统信息）、前端与 nginx 反代、定时任务与日志。
任何一项失败都会打印排查提示并以非 0 退出。

**只有自检全绿才算部署成功。**

### 3.3 装完立刻要做的三件事

```bash
# ① 改管理员口令：登录 → 右上角头像 → 个人中心 → 修改密码
#    （安装脚本已把它改成随机强口令，见 /root/.dms-credentials）

# ② 站点配置：系统管理 → 站点配置
#    设置站点名称、上传标识图（登录页/页头显示）、备案与版权

# ③ 建自己的账号与权限：系统管理 → 用户管理 / 角色管理
#    建议先建角色（勾权限），再建用户并分配角色；顶层文档区只能由超管创建
```

## 4. 配置说明（`/opt/dms/config/application-prod.yml`）

安装脚本从 `deploy/templates/application-prod.yml` 生成该文件，把 `@@XXX@@` 占位符
替换成本机实际值（口令来自凭据文件）。**权限 640 root:dms**，因为里面有口令。

需要人改的几项：

| 配置 | 含义 | 何时改 |
| --- | --- | --- |
| `dms.onlyoffice.document-base-url` | OnlyOffice 容器回拉本站文档的地址 | 装了 OnlyOffice 且服务器 IP 变了才改 |
| `dms.onlyoffice.enabled` | 是否启用在线预览（系统参数里也能改，即时生效） | 排障时可临时关掉 |
| `dms.upload.max-size` / `spring.servlet.multipart.*` | 单文件上限（默认 10GB） | 按现场需要 |
| `dms.tus.stale-hours` | 上传临时文件保留小时数（默认 48） | 磁盘紧张时调小 |
| `dms.media.token-ttl-minutes` | 图片/视频直链有效期（默认 120 分钟） | 通常不用改 |
| `server.address` | 只监听回环，**不要改成 0.0.0.0** | 不要改 |
| `sa-token.jwt-secret-key` | JWT 签名密钥，改后所有会话失效 | 怀疑泄露时改 |

两个易踩的点（已由脚本处理，但要知道原因）：

1. **profile 必须与配置文件名成对**。jar 里内置的 `profiles.active` 是 `dev`，
   systemd 里显式传了 `--spring.profiles.active=prod`（命令行优先级最高），
   因此外部配置必须叫 `application-prod.yml`。改一个不改另一个会导致"连不上数据库"。
2. **`spring.servlet.multipart.location` 必须写在可写目录**。jar 内置的 prod 配置写的是
   `/ruoyi/server/temp`（框架作者机器的路径），在 systemd `ProtectSystem=strict` 下不可写，
   上传站点图标、OnlyOffice 取文档都会失败。模板里已指向 `/var/dms/tmp`，
   并且该目录在 systemd 单元的 `ReadWritePaths` 白名单里。

### 系统参数（页面上的「系统参数」页）

有些配置存在数据库 `sys_config` 里，**页面改了即时生效、不用重启**，且优先级高于配置文件：

| 参数键 | 作用 |
| --- | --- |
| `dms.onlyoffice.enabled` | 在线预览开关（排障用） |
| `dms.onlyoffice.url` / `documentBaseUrl` / `internalUrl` / `secret` | OnlyOffice 相关地址与密钥 |
| `sys.watermark.enabled` / `sys.watermark.text` | 预览水印 |
| `sys.account.registerUser` | 是否允许自助注册（站点配置页也有开关） |

## 5. 反向代理与访问入口

nginx 是唯一对外入口（80）。`deploy/templates/nginx/dms.conf` 做四件事：

1. 前端静态资源（`/opt/dms/dist`），带缓存策略：`index.html` 永不缓存、`/assets/*` 缓存 30 天；
2. 后端反代：`/auth|system|api|upload|doc|...` → `127.0.0.1:8080`（**关闭缓冲**，
   否则大文件上下传会先落盘再转发，慢且占磁盘）；
3. OnlyOffice 同源反代 → `127.0.0.1:8081`（含带版本号前缀的资源与 `/doc/` 协作端点，
   这段正则必须排在后端反代之前，否则协作会话会 404）；
4. gzip 压前端大 chunk（默认只压 `text/html`，最大 chunk 1.1MB，不压会明显变慢）。

**只放一个配置文件**：`/etc/nginx/sites-enabled/` 里不要留 `.bak` 之类备份文件——
`include sites-enabled/*` 会把它们一起加载，于是出现
`conflicting server name "_"` 警告，谁生效取决于文件名字典序（本项目踩过这个坑）。

### HTTPS / 域名

默认只监听 80（内网）。若要走域名或 HTTPS：

```bash
# 1) 准备证书（内网自签或用内部 CA）
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout /etc/nginx/dms.key -out /etc/nginx/dms.crt -subj "/CN=dms.example.local"
# 2) 在 dms.conf 的 server 块前加一个 443 server（参考下面片段），80 段改为 301 跳转
#    server {
#        listen 443 ssl;
#        server_name dms.example.local;
#        ssl_certificate     /etc/nginx/dms.crt;
#        ssl_certificate_key /etc/nginx/dms.key;
#        client_max_body_size 0;      # 大文件上传必须放开
#        # 其余 location 与 80 段完全一致
#    }
# 3) 注意：OnlyOffice 回源地址（dms.onlyoffice.document-base-url）要同步改成 https 地址，
#    否则文档服务拉不到文件（自签证书还需在容器内信任该 CA）
nginx -t && systemctl reload nginx
```

docker logs -f onlyoffice                      # OnlyOffice 日志（装了才有）

## 7. 可选组件：OnlyOffice（Office 在线预览/编辑）

**不装也能用**：PDF/Office 预览回落为「服务端 LibreOffice 转 PDF + pdf.js」，
图片/视频/音频/文本/CAD 等不受影响。装了才有原生观感与在线编辑。

```bash
# 方式 A：用离线包（推荐，无需外网）
tar xf dms-release-1.0.0-onlyoffice.tar
cp dms-release-1.0.0-onlyoffice/onlyoffice/documentserver.tar /root/dms-release-1.0.0/deploy/
#   或直接指定路径：
./deploy/install-onlyoffice.sh --image-file /path/to/documentserver.tar

# 方式 B：服务器能上外网（docker pull 官方镜像）
./deploy/install-onlyoffice.sh --online
```

脚本会：装 Docker → 导入镜像 → 写 `/opt/onlyoffice/local.json`（JWT 关闭）→
复制中文字体并建立字体别名（**不装字体转换出的 PDF 中文是方框**）→
以 `127.0.0.1:8081` 启动容器 → 等健康检查 → 重载 nginx。

装完在「系统信息」页确认，并打开一个 docx/xlsx 验证。若编辑器白屏，
先看 `tail -f /var/log/nginx/dms-error.log`——通常是 OnlyOffice 的反代规则被后端正则抢了匹配。

## 8. 升级

```bash
# 1) 拿到新发布包并解压
tar xzf dms-release-1.0.1-core.tar.gz && cd dms-release-1.0.1

# 2) 升级（自动备份 → 替换 → 应用新迁移 → 重启 → 自检，失败自动回滚）
./deploy/upgrade.sh /root/dms-release-1.0.1
```

数据库迁移**只增不改**（历史迁移文件永不变更），所以回滚代码一般不需要回滚库。

## 9. 卸载

```bash
systemctl disable --now dms-app dms-backup.timer
rm -f /etc/systemd/system/dms-app.service /etc/systemd/system/dms-backup.{service,timer}
systemctl daemon-reload
rm -rf /opt/dms /var/dms /etc/nginx/sites-{available,enabled}/dms /etc/nginx/conf.d/00-dms-upgrade-map.conf
systemctl reload nginx
# 数据保留（默认不删）：PostgreSQL 库 dms、MinIO 数据 /opt/minio/data、备份 /opt/dms/backup
# 确认不再需要后再执行：runuser -u postgres -- dropdb dms; rm -rf /opt/minio/data
```

## 10. 故障排查速查

| 现象 | 先看哪里 | 常见原因 |
| --- | --- | --- |
| 服务起不来 | `tail -50 /opt/dms/logs/stderr.log` | 配置文件名与 profile 不匹配；数据库口令不对；8080 被占 |
| 页面 502 | `systemctl status dms-app`、`ss -ltnp \| grep 8080` | 应用没起来或没监听 8080 |
| 上传失败（大文件） | nginx 错误日志、`dms.upload.max-size` | nginx `client_max_body_size` 没放开（模板里是 0=不限制） |
| 上传卡住不动 | `du -sh /var/dms/tus` | 临时目录满 / 磁盘满；看 `TusCleanupJob` 日志 |
| 图片/视频不显示 | 浏览器控制台、`/api/doc/files/{id}/media` 返回 | 直链令牌过期（默认 120 分钟）或 `security.excludes` 缺 `/api/doc/media/**` |
| 文档预览白屏 | nginx 错误日志 | OnlyOffice 反代规则顺序；OnlyOffice 容器没起 |
| Office 预览中文方框 | OnlyOffice 容器字体目录 | 没复制中文字体到 `/opt/onlyoffice/fonts` |
| 上传站点图标报 `Read-only file system` | `grep ReadWritePaths /etc/systemd/system/dms-app.service` | 目录不在 systemd 可写白名单里（本项目踩过） |
| 定时任务没跑 | `systemctl list-timers dms-backup.timer` | timer 没 enable |
| 权限看起来不对 | 「系统信息」页 → 业务数据量 / 授权条数 | 授权是并集 + 禁止访问一票否决，见技术文档 3.1 |

更多排查与备份恢复见《04-运维手册.md》。
